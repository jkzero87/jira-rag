# Router tossing: the reassignment graph (experiment 5)

Generated by `scripts/router_tossing.py`; regenerated byte-identical on every run (do not edit by hand).

Population: the `router.text_dataset` issues (in-project, at least one component; n = 60505). **Initial** components are the components the issue had at creation, reconstructed exactly like `parent_components_asof`: the current list with every Component changelog entry after `created_at` undone, newest first (source: `bronze.jira_issue_raw`, `payload->'changelog'->'histories'`, `field='Component'`). **Final** components are the current ones — the label the router uses. Changed = initial != final, split into **late assignment** (initial empty -> has a component; not a toss) and **real toss** (initial non-empty and initial != final). Pairs: for a real-toss issue, every removed component x is paired with every added component y (edge x -> y). Periods: train < 2023-01-01, validation 2023, test >= 2024-01-01.
