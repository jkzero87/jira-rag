# Router hippocampus: embedding memory (experiment 2)

Generated by `scripts/router_hippocampus.py` on every run; never edit by hand.

**Question.** The `rolling` router (monthly retraining, as-of labels, V-token+balanced, C = 8; the variant selected in experiment 3, docs/router_recency.md) learns components only through tf-idf weights. Does an episodic memory of the training issues' embeddings, nearest neighbours or per-component prototypes, add routing accuracy when blended with it?

**Method.** For each month M (2023-01 .. 2026-11, 47 months) the training set is the `rolling` one: issues created before the first day of M whose as-of labels at that day are non-empty. Validation = the 2023 months (4733 issues); test = 2024 onward (15754 issues, data ends 2026-11-24). Ground truth = final components; a top-1 hit = the predicted component is one of them.

- **LR**: the `rolling` probability matrix (fit_balanced and make_predict of `scripts/router_recency.py`, unchanged).
- **kNN(k)**: `summary_desc` embeddings (Qwen3-Embedding-4B, 1024 dims, L2-normalised; norms asserted within 1e-05). The k most similar training issues by dot product; component score = sum of the similarities of the neighbours whose as-of label contains the component, divided by the sum of all k similarities. k in {10, 30, 100}.
- **Prototypes**: per component, the mean embedding of its training issues (as-of labels), re-normalised; score = softmax over components of (cosine x 20).
- **kNN-prior(k)**: the kNN(k) component score divided by that component's share of the month-M training issues (as-of labels), then renormalised to sum 1 over components. k in {10, 30, 100}.
- **Per-class 1-NN**: per component, the maximum cosine between the issue and any of its training issues (as-of labels); score = softmax over components of (max cosine x 20), the same temperature as prototypes.
- **Combined**: score = (1 - w) x LR + w x MEMORY, w in {0, 0.25, 0.5, 0.75, 1}, MEMORY any of the four memory sources. All sources score the same month-M class set (the components of the as-of training labels); a component missing from a source would score 0 there.

**Reproduction check.** w = 0 is asserted to reproduce `rolling` exactly: validation top-1 3462/4733 and test top-1 11579/15754 (docs/router_recency.md).

### f) Embedding gap fill

Before this experiment, 2682 router issues (created 2026-09-18 .. 2026-11-24) had no embedding: they existed only in `bronze.jira_issue_raw`, and `jira.issue_chunks` references `jira.issues`. `scripts/router_embed_gap.py` inserted them into `jira.issues` with `src/jira_rag/ingest.py --bronze-keys-file` (flatten and UPSERT of ingest.py; existing rows skipped) and embedded them with `src/jira_rag/embed.py --keys-file` for both strategies. The 59227 existing `jira.issues` rows kept the same count and (issue_key, summary, description) md5 `27a1d0ba1a692e0b1394be5aa940fc14`.

| table | before | after |
|---|---|---|
| `jira.issues` | 59227 | 61909 |
| `jira.issue_chunks[summary_only]` | 59227 | 61909 |
| `jira.issue_chunks[summary_desc]` | 59227 | 61909 |

Consistency check before writing (`scripts/embed_consistency_check.py`): the 20 smallest issue keys created in 2026-09 (SPARK-59140 .. SPARK-59159) re-embedded with the embed.py code path and compared with their stored vectors.

### Note on the test split

The test split was never used to choose anything in this experiment: the memory source, k, w and the margin thresholds are all chosen on validation only; test is reported as reference.

### Resumability

Per-month scores are cached at `scratch/hippocampus/<YYYY-MM>.npz` and skipped when present; delete the directory to force a rerun.
