# Router novelty detection (experiment 4)

Generated by `scripts/router_novelty.py` on every run; never edit by
hand.

**Question.** The selected variant of experiment 3, `rolling` (monthly
retraining, V-token+balanced, C = 8), can only predict components it
was trained on. Issues whose final components are all outside that
set are NOVEL and can never be routed correctly - yet their margin
and top-1 probabilities may still look high. How much of the
auto-routing at the 90% margin threshold is this, and does a
nearest-training-example signal (nn_sim) gate it out?

**Base model and reuse.** For each month M the model is the `rolling
variant of docs/router_recency.md: trained on the issues created
before the first day of M, predicting the issues created in M. The
fit function (`fit_balanced`), the month loop, the as-of training
labels and the validation/test split are reused from
`scripts/router_recency.py`; `choose_threshold` and `auto_stats`
from `scripts/router_confidence.py`. No training code is duplicated.

**Fit-function change (equivalence proof).** `fit_balanced` in
`scripts/router_recency.py` gained an optional argument
`return_train=False`; the default keeps the previous 4-element return
and identical behaviour. The 2024-01 month (train = 44743 issues) was fitted with the old call (4 elements) and with the new call (5 elements): predicted probabilities shape (384, 41), max abs diff 0.000e+00, np.array_equal True.

**Definitions (per month M).** known(M) = the set of components that
appear in at least one as-of training label of the month-M training
set (exactly the model's class set). An issue created in M is NOVEL
if none of its final components is in known(M). A novel issue
auto-routed at any threshold is wrong by definition (the predicted
component is a model class, hence in known(M), hence outside the
issue's final components).

**Signals (per issue, no new model).** top1 = top-1 probability;
margin = top1 - top2; nn_sim = max cosine similarity between the
issue's tf-idf vector and the month-M training matrix (sparse dot
product; tf-idf rows are asserted L2-normalised within 1e-6).

**Thresholds.** t90 = 0.75, the 90% margin threshold of `rolling`
in docs/router_recency.md (parsed from that doc and asserted to
equal choose_threshold on the recomputed rolling validation
margins). Gates s = the 1st, 2nd and 5th percentile of nn_sim of the
KNOWN-and-auto-routed VALIDATION issues at t90 (s = 0.1330, 0.1471,
0.1644 respectively) - never chosen with novelty labels. Test is
never used to choose anything; test numbers are reference only.

**Splits and months.** validation = the 2023 months (4733 issues);
test = created_at >= 2024-01-01 (15754 issues, data ends 2026-11-24).

### e) Gate: auto-route only if margin >= t90 and nn_sim >= s

s is the 1st / 2nd / 5th percentile of nn_sim of the KNOWN-and-
auto-routed VALIDATION issues at t90 (1243 such issues).

**Gate selected by the validation rule** (the gate with the fewest
validation novel auto-routes whose validation coverage loss vs no
gate is at most 2 pp): the 1st percentile (s = 0.1330): 0 validation novel issues still auto-routed vs no gate, coverage loss 0.3 pp (tie-break, if ever used: the smaller percentile)

**Test was never used to choose anything** (no variant, no threshold,
no gate); test numbers are reference only.
