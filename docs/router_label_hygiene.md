# Router label hygiene (experiment 7)

Generated by `scripts/router_label_hygiene.py`; the doc is regenerated
byte-identical on every run - do not edit it by hand.

**Population.** router text-dataset issues (in-project, >= 1 component),
n = 60505. **Periods** by `created_at`: train < 2023-01-01
(n = 40018), validation 2023 (n = 4733),
test >= 2024-01-01 (n = 15754).

**Selection protocol.** every variant is selected on the 2023 slice:
fit on train (created_at < 2023-01-01), score top-1 on the 2023 slice,
C grid {0.5, 2, 8}, tie -> smaller C. Test is never used for selection.

## 1. Component renames (evidence strictly before 2023-01-01)

**Method.** An issue's *initial* components are its current list with
every Component changelog entry after `created_at` undone
(`components_asof`, as in experiment 5). A rename X -> Y is supported
only if ALL of the following hold, using only data dated before
2023-01-01:

* **retired(X)** - no issue created in [2022-01-01, 2023-01-01) has X
  in its initial components;
* **current(Y)** - at least one issue created in that window has Y in
  its initial components;
* **burst** - at least 5 X -> Y replacement events (the issue lost X and
  gained Y, in either order, or one direct swap entry; one event per
  (X, Y) per issue) inside a 60-day window.

**Result.** mapping = `{'MLilb': 'MLlib', 'docs': 'Documentation'}`; applied to the
training labels before fitting. No issue created in 2023 or later
carries an old name (0 of 4733 validation rows,
0 of 15754 test rows carry `docs` or `MLilb`).

**Candidates.** the pairs with >= 1 pre-2023 replacement event, plus the
four pairs flagged in experiment 5 (tossing graph). Passing pairs first,
then the flagged ones:

| old | new | events | span | max 60-day cluster | last new X (init) | first new Y (init) | verdict |
|---|---|---|---|---|---|---|---|
| MLilb | MLlib | 7 | 2015-10-27..2016-07-07 | 6 (2016-07-07) | 2016-07-05 | 2014-03-12 | **rename** |
| docs | Documentation | 80 | 2016-07-07..2021-11-15 | 78 (2021-11-15) | 2021-10-30 | 2012-10-24 | **rename** |
| MLlib | ML | 24 | 2015-04-20..2019-12-27 | 5 (2016-03-21) | 2022-11-27 | 2014-09-15 | not a rename - X not retired (new MLlib issue on 2022-11-27); of the 32 issues created before 2023 that started with MLlib and ended with ML, only 32 completed the swap before 2023-01-01 (0 after, 0 never recorded) |
| R | SparkR | 33 | 2015-10-20..2020-12-15 | 28 (2015-12-07) | 2022-11-25 | 2015-04-09 | not a rename - X not retired (new R issue on 2022-11-25); of the 95 issues created before 2023 that started with R and ended with SparkR, only 32 completed the swap before 2023-01-01 (63 after, 0 never recorded) |
| ps | Pandas API on Spark | 2 | 2022-09-05..2022-09-05 | 2 (2022-09-05) | 2022-11-24 | 2022-05-17 | not a rename - X not retired (new ps issue on 2022-11-24); burst 2 < 5; of the 40 issues created before 2023 that started with ps and ended with Pandas API on Spark, only 2 completed the swap before 2023-01-01 (38 after, 0 never recorded) |

Every other considered pair (the remaining 239 of 244)
fails at least one criterion (no burst, X not retired, or Y not
current).

**Robustness.** the mapping is unchanged for every whole-day retirement
threshold T with 83 <= T <= 427 days before 2023-01-01 (i.e.
any threshold in (82, 428) days).

## 2. Multi-component issues

Issues with >= 2 final components, per period (`period_of`, experiment 5):

| validation | 4733 | 1109 | 23.4% |

The current single-label scoring code (`scripts/router_text_baseline.py`):

```python
def hit_counts(proba, names, actual, k):
    idx = topk_idx(proba, k)
    hit1 = hitk = 0
    for i, comps in enumerate(actual):
        cset = set(comps)
        if names[idx[i][0]] in cset:
            hit1 += 1
        if any(names[j] in cset for j in idx[i]):
            hitk += 1
    return hit1, hitk
```

A top-1 hit is counted when the predicted name is one of the issue's
FINAL components - identical to "any of the final components" by
construction, so both definitions give the same number below.
