# Router aging and recency (experiment 3)

Generated by `scripts/router_recency.py` on every run; never edit by
hand.

**Question.** The router was selected once, before 2024. As the data
ages, does a statically trained model keep up — and do recency-
weighted sampling or monthly retraining help?

**Base model.** Every variant is V-token+balanced: tf-idf
(sublinear_tf, min_df=3, 1-2 grams, 200k features) plus one-vs-rest
logistic regression with `class_weight="balanced"` (the pipeline of
`scripts/router_label_hygiene.py`), with **C = 8 fixed**. No C grid is
re-run in this experiment: C = 8 is the value experiment 7 selected
for V-token+balanced (docs/router_label_hygiene.md). The only fitting
code added here generalizes that pipeline to explicit per-row labels
(rolling months) and to `sample_weight` (recency).

**Splits and months.** train = created_at < 2023-01-01 (40018
issues); validation = the 2023 slice of train (4733 issues); test =
created_at >= 2024-01-01 (15754 issues, data ends 2026-11-24).
Months covered: 2023-01 .. 2026-11 (47 months).

**Variants.**

- `static`: trained once on created_at < 2023-01-01 (final labels)
  and applied to every month; the aging baseline. Its validation
  top-1 is asserted by the script to be 3298/4733 (69.7%), the
  documented V-token+balanced number.
- `recency`: same training set, `sample_weight = 0.5 ** (age_years /
  h)` with age = 2023-01-01 - created_at; h in {1, 2, 4} chosen on
  validation top-1 (tie -> smaller h).
- `rolling`: for each month M, trained on the issues created before
  the first day of M, predicting the issues created in M.
- `rolling+recency`: rolling plus the recency weights, age measured
  against the first day of M, h fixed at the h chosen by `recency`.

**Label rule (step 1).** Step 1 found an existing as-of builder:
`components_asof` in `scripts/router_parent_context.py:58` (the
builder the earlier experiments used for "labels as-of"). So the
training labels of every month M are the components as known at the
first day of M — the final component list with every Component
changelog entry on/after that day undone — and issues whose as-of
list is empty are left out of that month's training set. The ground
truth for the issues created in month M is their FINAL component
list, the same label definition every other experiment uses (a top-1
hit = predicted component is one of the issue's final components).
The fallback rule (train only on issues RESOLVED before the first
day of M, with their final labels) was not needed.

### Note on the test split

The test split was never used to choose anything in this experiment:
the half-life h, the margin thresholds and the variant selections
above are all made on validation only; test is reported as
reference.

### Resumability

Per-month prediction sets are cached at
`scratch/recency/<variant>/<YYYY-MM>.npz` and skipped when present;
delete the directory to force a rerun.
